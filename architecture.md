# Architecture

## Network (stack 03)
| Tier | Subnets | Route | Notable controls |
|---|---|---|---|
| Web | 10.20.0.0/24, 10.20.1.0/24 | Internet Gateway | ALB only; WAF attached; ALB security group is the only one open to 0.0.0.0/0 |
| App | 10.20.10.0/24, 10.20.11.0/24 | NAT Gateway | No inbound except from the ALB security group; egress 443 only |
| Data | 10.20.20.0/24, 10.20.21.0/24 | none | NACL allows only MySQL from app subnets; DB security group has no egress |

Security groups reference each other (ALB -> App -> DB) instead of CIDR ranges. VPC flow logs go to a
CloudWatch log group encrypted with the audit key.

## Encryption
- **At rest:** RDS, EBS, S3, Secrets Manager, SNS and SSM SecureString use the `data` CMK; CloudTrail, Config
  and flow logs use the `audit` CMK. Annual key rotation is enabled on both.
- **In transit:** ALB HTTPS with a TLS 1.2/1.3 policy and HTTP->HTTPS redirect; RDS `require_secure_transport=1`;
  S3 bucket policies deny requests where `aws:SecureTransport` is false.
- ALB-to-instance traffic is HTTP inside the VPC. For end-to-end TLS, add a certificate on the instances and an HTTPS target group.

## KMS access model
Key policies delegate to IAM (account root) and add two scoped statements: use of the key only *via* named AWS services
for principals in this account (`kms:ViaService` + `kms:CallerAccount`), and `CreateGrant` only when
`kms:GrantIsForAWSResource` is true. That is how EBS, RDS and Auto Scaling obtain grants without any human or
role being named in the key policy.

## Secrets
The RDS master secret is generated by Secrets Manager (never in a template or parameter), attached to the DB instance and
rotated every 30 days by the hosted MySQL single-user rotation Lambda running in the app subnets. Every `GetSecretValue`
call appears in CloudTrail.

## Detection and response
```
GuardDuty (>= 7) ----\
                      >-- EventBridge --> Lambda --> tag + EBS snapshot + quarantine SG --> SNS email
Security Hub CRITICAL-/
Config rules --> SSM Automation (S3 public/unencrypted, SSH open to the world)
```
Quarantined instances fail ALB health checks, so the Auto Scaling group replaces them; the snapshots and tags remain for investigation.

## IAM
The app role is capped by `<project>-app-boundary`: even `AdministratorAccess` attached to it could not touch IAM,
Organizations, key deletion or the audit/detection services. SCPs add the same guard rails at organization level.

## Monitoring (CIS alarms)
CloudTrail also streams to an encrypted CloudWatch Logs group. Metric filters and alarms cover root usage, unauthorized
API calls, console login without MFA, CloudTrail changes and KMS key disable/deletion. Alarms publish to the same encrypted
SNS topic the incident-response Lambda uses (the data key policy lets CloudWatch publish to it).

## Private AWS access
An S3 gateway endpoint on the app route table keeps S3 traffic off the NAT gateway at no cost.
